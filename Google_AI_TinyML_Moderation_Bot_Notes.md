## ⚡ 2. Core Technical "Gold Nuggets" (Hardware \& Inference Realities)

* **The Tokenization Bottleneck:** CPU time spent converting raw slang into token IDs can exceed the actual neural network inference time.

  * *Strategy:* Restrict vocabulary size (e.g., 10k–15k instead of 30k+) to drastically shrink the embedding layer footprint and maximize processing speed.
* **Hardware Register Alignment (Power of 2):** Parallel computing architectures (AVX-512, ARM Neon) require memory alignment.

  * *Strategy:* Stick to dimensions that are multiples of 32, 64, or 128. A model configuration with `hidden\_dim=256` will often yield lower latency and fewer cache misses than an unaligned configuration like `hidden\_dim=230`, despite having more parameters.
* **Student Network Setup Evaluation:** Compare structurally distinct internal mechanics rather than just cutting layers:

  * *Depth-reduced:* Keeps hidden dimensions wide but slashes vertical layers (e.g., DistilBERT style).
  * *Width-reduced \& Bottlenecked:* Slashing hidden widths and using bottleneck sequences (e.g., MobileBERT style) to reduce matrix multiplication workloads on CPUs.
* **Online Benchmarking Constraints:** Never measure performance solely on massive batch sizes. Real streaming bots handle messages sequentially. Always evaluate **Batch Size = 1 (Streaming/Online Latency)** to uncover true kernel invocation overhead.
* **Quantization Control Baseline:** Maintain `FP32`, `FP16`, and `INT8` variations of every setup. A slightly larger network architecture that quantizes cleanly to `INT8` without dropping accuracy is often better than a microscopic model that breaks under quantization.

## 📊 3. Dataset Strategy \& Data Selection

* **Target Size:** You do not need gigabytes of data for student distillation. Aim for a balanced selection of **10,000 to 50,000 accurate, labeled rows** per target classification class. Skip the 118 GB raw Discord dump.
* **The Labeled Advantage:** Supervised Fine-Tuning (SFT) is mandatory to teach a model the semantic definition of toxicity.
* **The Two-Step Pipeline Option:**

  1. *Domain Adaptation:* Execute minimal Masked Language Modeling (MLM) pre-training on unlabeled streaming logs (like the Hugging Face `twitch\_chat` dataset) to map contextual slang (`PogChamp`, `Kappa`, `EZ`).
  2. *Task Distillation:* Fine-tune a robust teacher (e.g., RoBERTa or ModernBERT) on cleanly labeled sets like **Jigsaw** or **OLID**, then distill that knowledge down into your targeted student matrix arrays.

## 🧹 4. Real-time Slang \& Chat Data Cleaning Guide

* **Automated Bot Filtering:** Strip text anomalies generated by server metrics or level bots (`Congrats on leveling up!`, `\[Trivia]`, `!points`). They inject artificial language rules that mask actual toxic data arrays.
* **Strict Copypasta Deduplication:** Enforce strict unique text filtering passes using a string hashing filter (like MD5) or context window constraints. Toxic copypastas repeated thousands of times will cause extreme parameter overfitting.
* **Never Normalize Camouflaged Profanity:** Do not use string replacement algorithms to change obfuscated phrasing like `sh1t` or `F\_u\_c\_k` into standard text. A Deep Learning classifier must actively learn to intercept intentional characters and symbol adjustments designed to bypass native regex filters.
* **Emote Collapse:** Chat behaviors frequently consist of massive repeating blocks (`:3 :3 :3 :3`). Tokenizers handle foreign symbols poorly, mapping them to expensive `\[UNK]` arrays. Write logic to compress repeating emojis down to a single instance to reduce sequence array context lengths and maintain low inference processing time.
